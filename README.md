# KeyboardTune · 键盘打字旋律音效（Windows）

打字的时候，键盘在你手底下哼一段旋律。

后台常驻、无窗口、无控制台，全局监听每一次按键，按下瞬间播放该键固定音高的短音；
26 个字母键音高互不重复，中文拼音的高频声母落在自然大调骨干音级、韵母落在协和邻音，
所以连续打字（尤其打中文）听起来是连贯的乐句而不是随机噪声。托盘里可以调音量、
设置开机自启动、退出。

---

## 1. 安装

需要 Windows 10/11 与 Python 3.8+（开发验证环境为 Python 3.12.10）。

```powershell
# 建议用虚拟环境
python -m venv .venv
.\.venv\Scripts\activate

# 关键依赖安装命令
python -m pip install -r requirements.txt
```

四个依赖各自负责什么：

| 依赖 | 用途 | 必需性 |
| --- | --- | --- |
| `pynput` | 全局键盘低级钩子（只读，不拦截） | 必需，缺了没有声音 |
| `pystray` | 系统托盘图标与右键菜单 | 建议装，缺了程序仍运行但无法从菜单退出 |
| `Pillow` | 程序内现画键盘图标（不依赖图片文件） | 随 pystray |
| `pygame` | 音频后端：24 通道真复音、5.8ms 延迟 | 可缺，自动回退到系统 `winsound` |

> `winsound` 是 Windows 自带的标准库，不需要安装；它只有一个发声通道（新音取代旧音），
> 用作 pygame 不可用时的兜底。`simpleaudio` 没有实现：它的 `WaveObject` 只接受文件路径，
> 而本程序所有采样都在内存里，为换个后端把采样写盘不划算（`audio.BackendBase`
> 之上加一个实现即可扩展）。

## 2. 运行

```powershell
# 正式使用：静默后台运行，无窗口无控制台，只在托盘出现一个键盘图标
pythonw main.pyw

# 调试运行：日志同时打到终端
python main.py --debug

# 查看按键-音效映射表（音名/音色）
python -m keyboard_tune --dump-map

# 只跑规则自检，不启动监听
python -m keyboard_tune --selftest
```

启动后：托盘（通知区域）出现键盘图标。若通知区被折叠，点 `^` 展开就能看到。

程序用命名互斥体保证**只跑一个实例**（两个实例会把每次按键叠成两声），第二次启动会
直接提示已在运行并退出。

## 3. 托盘菜单

| 菜单项 | 行为 |
| --- | --- |
| `当前音量 N%` | 只读状态行 |
| `音量 ▶ 调高/调低 5%` | 逐级调节，立即生效 |
| `音量 ▶ 10%…100%` | 档位单选（原生菜单没有滑杆控件，按需求允许的"音量加减选项"实现） |
| `静音` | 勾选框；保留原音量值，取消勾选即回到原音量 |
| `开机自启动` | 勾选框；写/删当前用户注册表 Run 项，不需要管理员权限 |
| 状态行 | 当前音频后端、覆盖按键数、待渲染槽位数 |
| `退出程序` | 停止全部音效 → 卸载键盘钩子 → 落盘配置 → 移除托盘图标 → 进程结束 |

配置保存在 `%APPDATA%\KeyboardTune\config.json`（音量/静音/自启动/后端选择），
写入用"临时文件 + 原子替换"，程序被强杀也不会留下半个坏文件；文件损坏时自动
备份为 `config.json.bak` 并回落默认值。开机自启动以**注册表实际状态为准**：
每次启动都会和注册表对账，手删注册表项也会被纠正。

## 4. 键盘适配

- **基准是 104 键全尺寸键盘**：`keyboard_tune/layout.py` 按物理位置列出全部 104 个键，
  带分区（主键区 / 功能键区 / 状态键区 / 编辑方向键区 / 小键盘区）与行列坐标，
  行列坐标同时用于"相邻"判定。
- **按键身份是虚拟键码 VK**，不是字符。VK 编码的是物理位置，与键盘配列无关：
  87 键少了小键盘区、68 键少了独立功能/编辑区、61 键只剩主键区，**共有按键的
  VK 完全一致，因此映射逐键保持不变**；缺的键自然没有事件，不会报错。
- 遇到不在 104 键基准内的键（笔记本多媒体键、ISO `<>` 键等）落到
  `notes.FALLBACK_SLOT`，仍是"有反馈且不崩"，只是用一个中性音高。
- 覆盖范围：26 字母、主数字排、全部符号键、F1–F12、PrintScreen/ScrollLock/Pause、
  四个方向键与插入/删除/首页/尾/上/下、全部修饰键（左右 Shift/Ctrl/Alt、Win、菜单键）、
  空格/回车/退格/Tab/Esc、小键盘 0–9 + − × ÷ . Enter NumLock 全部有独立音效。

## 5. 旋律化规则怎么落的

音高表不靠手拍：`scripts/build_note_map.py` 是一个约束求解器（AC-3 弧一致化 +
MRV 回溯 + 分支定界 + 坐标下降/2-opt 精修 + 随机重启），输入是
`scripts/pinyin_model.py` 统计出的拼音连击权重（敲一个拼音时前后相邻敲击的字母对），
输出是满足全部硬约束、并使软代价最小的 26 字母音高表。产出后被固化成
`keyboard_tune/notes.py` 里的静态表。

硬约束（`tests/test_mapping_rules.py` 独立复验，不复用求解器的判定函数）：

| 编号 | 内容 |
| --- | --- |
| H1 | 26 个字母音高互不重复，音域 A2–A5（恰好 3.00 个八度，中音区为主） |
| H2 | 非字母键允许复用音高，但**物理相邻的按键绝不与相邻键同音高** |
| H5 | 连击频次前 8 的声母（c d g h l n s z）全部落在自然大调骨干音级 1-3-5 |
| H7 | 韵母 a o e i u v 落在大调自然音/协和邻音（do re mi fa sol la），且不抢占骨干音位；主音 C4 归最高频韵母 a |
| H8 | 常用连击（每个字母频次前 2 的搭档 + 所有权重 ≥1000 的重音节 + 招牌组合键序）不得构成小二度、大七度、三全音、小七度 |
| H9 | `zh+ong` / `sh+ang` / `j+ing` 涉及的每一对按键都是三度 / 四·五度 / 六度 |
| H3 | 空格 = C3、回车 = G3（纯五度收束），小键盘回车 = A2 —— 低音区根音，起乐句停顿作用 |
| H4 | 音区 = 键盘分区 = 一个音色家族（主键区 key / 功能状态键 tick / 编辑方向键 soft / 小键盘 warm）；同家族内 a/b 两个细微变体按棋盘格 `(row+col)%2` 交替，于是**相邻按键必不同音色**与**同音区质感统一**同时成立 |

软目标（在硬约束之内尽量优化，代价函数加权）：次要声母优先五声正音、变化音只留给
最低频的键；越常用的键越贴近中音区 C4–C5；残余不协和连击按权重最小化。

### 需求里有三条是数学上过约束的，下面是量化证据与本项目的处理口径

运行 `python scripts/build_note_map.py --prove` 会打印这些计数：

1. **"每个声母都在骨干音级"与"26 音互不重复"冲突。** 3 个八度内骨干音（1/3/5 级）
   只有 9 个音位，主音归 a 后只剩 8 个，而需求点名的声母有 21 个（20 个字母）。
   → 处理口径：按连击频次取**前 8 个声母**作硬约束（结果确实 8/8 命中），其余声母
   要求落在五声正音（同样协和，只是不是 1-3-5）。
2. **"2~3 个八度 + 大调色彩 + 26 音互不重复"至少要 4 个变化音。** A2–A5 内自然音只有
   22 个，26 个互不重复的音高至少需要 26−22 = 4 个变化音。但"4 个变化音"的解与
   H5/H8 联立不存在，当前表用到 6 个变化音（`f j k q r x`），全部落在频次不入前 8
   的次要声母/半元音上。
3. **"每个声母 × 每个韵母头字母都避开小二度/大七度"无解。** 韵母若按需求取五声正音，
   其左右半音邻级被全部封死，3 个八度内只剩 15 个可用音高，而声母需要 20 个。
   → 处理口径：按需求原文的"**常用**拼音组合"界定硬约束范围，权重 ≥1000 的连击
   全部硬约束，其余作为软代价最小化。这个边界已经顶到墙：把硬约束阈值从 1000
   降到 700，严格 H5 口径下搜索在 2568 个节点内穷举完全部空间，**解不存在**
   （未触到节点预算，是穷举结论而不是"没搜到"）。

最终表的验收结果：

- `python tests/test_mapping_rules.py`：**15/15 通过**（H1–H9 逐条独立复验）
- H5 需求点名的最高频 8 个声母 **8/8 命中**骨干音级（c d g h l n s z）
- H8 硬约束连击（权重 ≥1000 的部分）不协和音程 **0 处**；招牌组合 **全部 OK**
- 硬约束集覆盖的连击权重占总连击权重 **90.5%**（即九成以上的实际敲键对受硬约束保护）
- 相邻同音高 **0 例**、相邻同音色 **0 例**（全部 104 键逐对检查）
- 残余不协和只出现在低频连击上：18 处小二度/大七度的最大权重 508（对比硬约束
  下界 1000），三全音仅剩 2 处（权重 108 与 3）

## 6. 性能指标（实测）

`python tests/check_resources.py 10 5` 的实测口径（完整链路：音频后端 + 71 个槽位
全部渲染 + 全局钩子 + 托盘图标；每窗 10s 共 5 窗，丢弃热身窗后按**最坏窗**判定）：

| 指标 | 需求 | 实测 |
| --- | --- | --- |
| 常驻内存 | ≤50MB | 工作集峰值 **45.4MB**（其中采样仅 1.42MB，其余是 CPython+SDL+Pillow+pystray 运行时；同样含钩子与托盘、回退到 `winsound` 时为 **29.8MB**） |
| 空闲 CPU | ≤1% | **最坏窗 0.62%**，稳态均值 0.16–0.35%（预渲染是启动期一次性开销，约 1.4s，已被丢弃的热身窗吃掉） |
| 按键延迟 | ≤50ms | SDL buffer 256 帧 = **5.8ms**，按键路径只有"查表 + 一次后端调用" |
| 复音 | 多键同响 | 24 通道；通道占满时 `find_channel(True)` **抢用最旧通道**（打断而非排队），从根上避免音效堆积 |
| 不干扰输入 | 100% 保留 | 回调永不返回 `False`，pynput 钩子为只读低级钩子 |

> 空闲 CPU 这个数字经历过一次口径修正：单窗口采样会把"SDL 混音线程建立 + 延迟加载
> DLL + 首次 GC"的一次性开销算进空闲占用，实测在同一份代码上跳出过 1.37%，看似超红线。
> 改成"丢弃首窗 + 按最坏窗判定"后可复现地落到 0.62% 以下。顺带验证了 SDL buffer 从 256
> 提到 512/1024 并**不能**降低稳态开销（三档最坏窗都是 0.31%），所以保留 256 换最低延迟。

其他稳健性设计：
- **Windows 自动重复抑制**：记录按下/释放状态，长按不刷音；超过 1s 仍收到"已按下"
  视为释放事件丢失并自愈。
- **监听看门狗**：钩子线程若因休眠/会话切换/驱动异常终止，5s 内检测到并重建监听器，
  避免"程序在跑但没声音"。
- **异常兜底**：`sys.excepthook` 与 `threading.excepthook` 都写日志不弹窗
  （`SetErrorMode` 关掉模态错误对话框），回调内部异常被吞掉以免终止钩子线程。
- 日志：`%APPDATA%\KeyboardTune\run.log`（批量落盘、超 512KB 自动截断）。

## 8. 自检与回归

```powershell
python tests\test_mapping_rules.py   # 映射规则（一/二/五条全部条款）
python tests\test_runtime.py         # 运行时链路（会真的响两声）
python tests\check_resources.py 10 5     # 内存 / 空闲 CPU（每窗 10s × 5 窗，按最坏窗判定）
python scripts\build_note_map.py --prove --budget 200000 --iters 30   # 重新求解映射表
```

## 9. 已知限制（如实说明）

- **主 Enter 与小键盘 Enter 无法区分**：低级钩子给出的 VK 都是 `0x0D`，扩展键标志
  pynput 不暴露。小键盘 Enter 因此使用主 Enter 的音效（映射表里仍为它准备了独立音高，
  将来若拿到扩展码可直接启用）。
- **NumLock 关闭时**，小键盘数字键上报的是方向/首页等 VK，此时发的是编辑区音效。
- 托盘音量是**档位 + 逐级加减**，不是滑杆：pystray 走系统原生菜单，原生菜单里没有
  滑杆控件。需求允许这一形式。
- 音量优先按通道音量实现（pygame），回退到 `winsound` 时按 5% 档位重算采样并缓存。
- 非 104 键基准上的多媒体键（音量键、浏览器键等）走兜底音，不参与乐理约束。
- 打包成 exe 后可直接把 `main.pyw` 用 PyInstaller `--noconsole` 打包，`autostart.py`
  会识别 `sys.frozen` 并把注册表项指向 exe 自身。
